# LABTRACK Final Architecture

## Project Title

**LABTRACK: Design and Development of a Hardware Asset Management System with App-Based Equipment Booking and Defect Reporting for the College of Computing Studies, Pampanga State University, Using Quick Response Code Technology**

## Summary

LABTRACK is a cloud-hosted asset management system with a web application for administrators and an Android mobile application for instructors. Each physical equipment item has a unique QR code generated by an administrator. Instructors scan the QR code to view equipment details, request bookings, submit defect reports with photo evidence, and communicate with administrators through contextual ticket chat.

The implementation uses a TypeScript monorepo, Next.js App Router for the web application, Expo for the Android application, and Supabase for authentication, database storage, file storage, realtime updates, and row-level security.

## System Architecture

- **Web app:** Next.js App Router for Super Admin and Admin workflows.
- **Mobile app:** Expo Android app for Instructor workflows.
- **Backend:** Supabase Postgres, Auth, Realtime, Storage, and RLS.
- **Deployment:** Vercel for web, EAS Build for Android, hosted Supabase for backend services.
- **Shared code:** TypeScript package for domain constants, validation helpers, QR helpers, and database-facing types.

## Roles

- **Super Admin:** manages Admin accounts and system settings.
- **Admin:** manages assets, QR codes, bookings, checkout/return, defect triage, and ticket communication.
- **Instructor:** scans QR codes, views asset details, requests bookings, reports defects, uploads photos, and chats with admins.

## Core Workflows

- **Asset and QR setup:** Admin creates an asset, generates a QR code, downloads or prints the label, and attaches it to the equipment.
- **QR scan:** Instructor scans a QR code and sees asset details, availability, booking action, and defect action.
- **Booking:** Instructor submits a booking request; Admin approves, rejects, checks out, and returns the item.
- **Defect reporting:** Instructor submits a defect report; Admin triages the report and updates the asset's operational status when needed.
- **Realtime communication:** Each booking or defect report has a ticket thread with persisted realtime messages.
- **Notifications:** In-app and Android push notifications alert instructors about booking status, defect status, and chat replies.

## Security Model

All exposed Supabase tables use Row Level Security. Instructors can only access their own operational records and limited asset details through valid active QR codes. Admins manage operational records. Super Admins manage higher-level access and system settings. Service-role credentials remain server-only.

## V1 Scope

V1 is Android-only for mobile, online-first, cloud-hosted, and built around individual physical asset tracking. It excludes student accounts, department-head approvals, iOS support, consumable inventory, offline sync, and mandatory QR custody scans.
